# ADR-0002: Базовая сущность и базовый репозиторий

**Status:** Accepted (уточняет решение 1 и пункты «Тип id», «Миграции схемы» из ADR-0001)
**Date:** 2026-11-03
**Deciders:** владелец бота

## Context

В ADR-0001 у каждой сущности был свой набор методов-намерений и свой способ хранения id: заметки и
задачи — общий `int`-счётчик, сессии и настройки — словари по chat id, пользователи — список user id,
статистика — без id. Удаление — физическое. Владелец попросил единый вид записей:

- базовая сущность: `Id` (ShortGuid), `SoftDeleted`, `SoftDeletedDate`; внешний id (Telegram) — в `ExternalId`;
- базовый репозиторий с виртуальными методами, которые репозиторий сущности при необходимости
  переопределяет, реализуя свою логику работы с базой.

Ограничения ADR-0001 остаются: два процесса (бот и MCP-сервер), атомарные операции, три провайдера.

## Decision

1. **`Entity`** (Domain): `Id: ShortGuid`, `ExternalId: string?` (уникален в пределах вида сущностей),
   `SoftDeleted`, `SoftDeletedDate`. Наследники: `Note`, `TaskItem`, `AllowedUser`, `ChatSession`,
   `ChatSettings`, `UsageRecord`. Одиночные значения (`rate_limit`, `digest_state`) — не сущности.
2. **`ShortGuid`** — value-type над `Guid` версии 7 (растёт со временем), в тексте 22 символа base64url.
   В PostgreSQL — `uuid`, в SQLite — текст `N` (тот же порядок сортировки), в JSON — короткая строка.
3. **`IRepository<T>`**: `Get`, `GetByExternalId`, `GetAll`, `Add`, `Update`, `Delete` (мягкое), `Restore`.
   Интерфейсы сущностей наследуют его и добавляют методы-намерения — они остаются, потому что
   атомарность (решение 1 ADR-0001) по-прежнему нужна.
4. **Базовый репозиторий в каждом провайдере** (`PostgresRepository<T>`, `SqliteRepository<T>`,
   `JsonRepository<T>`): все методы `IRepository<T>` — `virtual`; наследник описывает таблицу
   (`Table`, `Columns`, `Values`, `Read`) или порядок (`Sort`) и переопределяет то, что нужно.
   Для наследников — `Upsert` по `ExternalId` и `DeleteByExternalId`.
5. **Мягкое удаление везде**: методы-намерения и выборки не видят удалённых записей; снимок
   (`Export`/`Import`) переносит их вместе с отметками. Повторное добавление по `ExternalId`
   восстанавливает ту же запись (тот же `Id`).
6. **Версия схемы** в хранилище (`schema_version`, `schema.json`). `EnsureCreated` обновляет версию 1
   до 2 сам, в одной транзакции (Json — под мьютексом `schema.json`, старые файлы — в `v1-backup/`).

## Options Considered

### Вариант A: Общий базовый SQL-репозиторий с диалектами (Postgres + SQLite в одном коде)
**Pros:** меньше дублирования SQL. **Cons:** диалекты расходятся в типах (uuid/text, timestamptz/тики,
массивы/JSON), поиске без учёта регистра, блокировках; появляется слой абстракции диалекта, а
провайдеров всего два SQL-ных. Отложено: пересмотреть, если появится третий SQL-провайдер.

### Вариант B: Базовый репозиторий на провайдер (выбран)
**Pros:** базовый класс прячет общие колонки, приведение типов и мягкое удаление; репозиторий
сущности — это описание таблицы плюс методы-намерения; переопределения точечные (COPY для журнала
в Postgres, дописывание строки в Json). **Cons:** три базовых класса.

### Вариант C: EF Core
Отвергнут по тем же причинам, что в ADR-0001 (файловый провайдер, атомарные намерения, старт MCP).

## Trade-off Analysis

**ShortGuid вместо «#12».** Пользователь больше не видит коротких номеров; на практике id передаёт
агент (MCP-инструменты принимают id строкой и проверяют формат), а в сообщениях Telegram id не
показываются — только в данных кнопок (22 символа укладываются в лимит 64 байта). Взамен — id не
зависят от провайдера и счётчика, перенос и слияние данных не ломают нумерацию.

**Мягкое удаление и рост данных.** Удалённые записи остаются навсегда. Для личного бота объём
ничтожен; если понадобится — отдельная очистка `soft_deleted_date < …`.

**`ExternalId` — строка.** Telegram id — `long`, но строка покрывает любые будущие внешние системы;
`Entity.External(long)` даёт единый формат.

## Consequences

- Легче: новая сущность — класс, описание таблицы и только её собственные методы; общие операции
  и мягкое удаление готовы. Удалённое восстанавливается.
- Сложнее: изменение существующей таблицы требует шага обновления схемы во всех трёх провайдерах.
- Обновление существующей базы происходит при первом старте новой версии — сделайте резервную
  копию (`pg_dump`).
